# Result data

`rank_traces.json` holds the per-step x per-rank ECO timeline for every
measured configuration (13 runs x 8 ranks x 256 rows x 18 slots).

Layout:

```json
{
  "slot_names": [...18 names...],
  "note": "...units and wrapping...",
  "groups": {
    "<group>": {
      "<arm>": {
        "ms_per_step": 20.41,
        "ir": 1.0262,
        "slots_per_rank": 52,
        "tokens_per_rank": [...8...],
        "ranks": [ {"rank":0, "tl_rows":[[...18...] x 256]}, ... ]
      }
    }
  }
}
```

Values are **microseconds** stored in int32: past ~36 minutes of device uptime
they wrap negative, but a difference inside one row stays exact. Slot 14
(`norep_wait_plan`) is a **duration**, not a timestamp.

The full per-run JSON (which additionally holds `load_detail`, `ir_detail` and
the raw request log) is ~1 MB each and is regenerated by
`scripts/run_matrix.sh`; only the merged timeline is committed.

## `TR3.json` — 单层完整时间轴（README 的 pull 表 + GEMM 表数据源）

BS=128（`seqs_per_rank=16`），`GC_MOE_EPLB_EXTRA_PER_RANK=8 GC_MOE_ECO=1`，
`wb=260 wa=111`，100 步 warmup + 10 步测量，
`GC_MOE_ECO_TRACE=1 GC_MOE_PULL_TRACE=1 GC_MOE_FINE_TRACE=1
GC_MOE_FINE_MIN_EPOCH=8300 GC_MOE_SM90_BLOCK_READY=0`。

重排结果 `max_copies=2 / replicated=64`（384 专家 = 320 单副本 + 64 双副本）。

每 rank 的 `eco_trace.ranks[i]`：

* `fine_rows` — 8 词记录 `[t_us, type, id, a0, a1, a2, epoch, 0]`，
  type 1=`slot_begin` 2=`slot_end` 3=`wait_plan`(a0=0 begin/1 released)
  4=`claim_spin` 5=`claim_ok` 6=`task_begin` 7=`task_end`，
  `t_us` 是 **uint32 微秒**（回绕，做差即可）。
* `tl_rows` — `eco_tl[256][21]`，`tl_step` 指向本次记录的行；
  `[8]=push_begin` 是基准，`[7]=plan_end`，`[9]=push_end`，
  `[10..13]=pull_norep/rep_begin/end`。
* `eco_meta` — `int32[6616]`：`[0,16)` 头部，`[16,16+E*16)` copies，
  `[16+E*16, +448)` phy2log，`[.., +8)` num_fixed。

```
python3 scripts/gen_pull_table.py runs/TR3.json 0   # pull 表
python3 scripts/gen_gemm_table.py runs/TR3.json 0   # GEMM 表
```
