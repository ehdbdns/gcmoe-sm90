# Result data

`rank_traces.json` holds the per-step x per-rank ECO timeline for every
measured configuration (13 runs x 8 ranks x 256 rows x 18 slots).

Layout:

```json
{
  "slot_names": [...18 names...],
  "note": "...units and wrapping...",
  "groups": {
    "<group>": {
      "<arm>": {
        "ms_per_step": 20.41,
        "ir": 1.0262,
        "slots_per_rank": 52,
        "tokens_per_rank": [...8...],
        "ranks": [ {"rank":0, "tl_rows":[[...18...] x 256]}, ... ]
      }
    }
  }
}
```

Values are **microseconds** stored in int32: past ~36 minutes of device uptime
they wrap negative, but a difference inside one row stays exact. Slot 14
(`norep_wait_plan`) is a **duration**, not a timestamp.

The full per-run JSON (which additionally holds `load_detail`, `ir_detail` and
the raw request log) is ~1 MB each and is regenerated by
`scripts/run_matrix.sh`; only the merged timeline is committed.
