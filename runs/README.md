# Result data

`rank_traces.json` holds the per-step x per-rank ECO timeline for every
measured configuration (13 runs x 8 ranks x 256 rows x 18 slots).

Layout:

```json
{
  "slot_names": [...18 names...],
  "note": "...units and wrapping...",
  "groups": {
    "<group>": {
      "<arm>": {
        "ms_per_step": 20.41,
        "ir": 1.0262,
        "slots_per_rank": 52,
        "tokens_per_rank": [...8...],
        "ranks": [ {"rank":0, "tl_rows":[[...18...] x 256]}, ... ]
      }
    }
  }
}
```

Values are **microseconds** stored in int32: past ~36 minutes of device uptime
they wrap negative, but a difference inside one row stays exact. Slot 14
(`norep_wait_plan`) is a **duration**, not a timestamp.

The full per-run JSON (which additionally holds `load_detail`, `ir_detail` and
the raw request log) is ~1 MB each and is regenerated by
`scripts/run_matrix.sh`; only the merged timeline is committed.

## `TR3.json` — 单层完整时间轴（README 的 pull 表 + GEMM 表数据源）

BS=128（`seqs_per_rank=16`），`GC_MOE_EPLB_EXTRA_PER_RANK=8 GC_MOE_ECO=1`，
`wb=260 wa=111`，100 步 warmup + 10 步测量，
`GC_MOE_ECO_TRACE=1 GC_MOE_PULL_TRACE=1 GC_MOE_FINE_TRACE=1
GC_MOE_FINE_MIN_EPOCH=8300 GC_MOE_SM90_BLOCK_READY=0`。

重排结果 `max_copies=2 / replicated=64`（384 专家 = 320 单副本 + 64 双副本）。

每 rank 的 `eco_trace.ranks[i]`：

* `fine_rows` — 8 词记录 `[t_us, type, id, a0, a1, a2, epoch, 0]`，
  type 1=`slot_begin` 2=`slot_end` 3=`wait_plan`(a0=0 begin/1 released)
  4=`claim_spin` 5=`claim_ok` 6=`task_begin` 7=`task_end`，
  `t_us` 是 **uint32 微秒**（回绕，做差即可）。
* `tl_rows` — `eco_tl[256][21]`，`tl_step` 指向本次记录的行；
  `[8]=push_begin` 是基准，`[7]=plan_end`，`[9]=push_end`，
  `[10..13]=pull_norep/rep_begin/end`。
* `eco_meta` — `int32[6616]`：`[0,16)` 头部，`[16,16+E*16)` copies，
  `[16+E*16, +448)` phy2log，`[.., +8)` num_fixed。

```
python3 scripts/gen_pull_table.py runs/TR3.json 0   # pull 表
python3 scripts/gen_gemm_table.py runs/TR3.json 0   # GEMM 表
```

## `R5_64.json` — README 两表的数据源（ECO half-SM 修复后）

BS=64（`seqs_per_rank=8`），`GC_MOE_EPLB_EXTRA_PER_RANK=8 GC_MOE_ECO=1`，
`wb=260 wa=111`，100 步 warmup + **100 步测量**，
`GC_MOE_ECO_TRACE=1 GC_MOE_PULL_TRACE=1 GC_MOE_FINE_TRACE=1
GC_MOE_FINE_MIN_EPOCH=8300 GC_MOE_SM90_BLOCK_READY=0`。

重排结果 `max_copies=3 / replicated=58`；每 rank 39 单副本 + 17 副本槽。

⚠️ **两个已知陷阱**（踩过）：

1. `fine_rows` 的 epoch（8300–8321）与 `tl_rows` 的 `step_tag`（10145–10400）
   **不重叠** —— `tl_rows` 是最近 256 步的环形缓冲，`fine_rows` 是
   `FINE_MIN_EPOCH` 之后最先填满的 65536 条。取时间基准必须用 `fine_rows`
   自己的首个 `slot_begin`。
2. 生成 pull/GEMM 表用：

```
python3 scripts/gen_pull_table.py runs/R5_64.json 0 8300   # pull 表
python3 scripts/gen_gemm_table.py runs/R5_64.json 0        # GEMM 表
```

## `x16/` — 16 个实验（4 臂 x 4 档 BS），2026-11-09 重测

`X16_<BS>_<arm>.json`，arm = `vanilla` / `random` / `rr` / `eco`。

只保留 `load_detail` + `ir_detail`（逐 rank 指标）以控制体积；
**`X16_128_eco.json` 额外带完整 `eco_trace`（8 rank 的 `fine_rows` + `tl_rows` +
`eco_meta`）**，README 的两张 trace 表就从它生成。

配置：BS = 32/64/128/256（`seqs_per_rank` = 4/8/16/32），
100 步 warmup + **100 步测量**，`GC_MOE_SM90_PULL_TMA=1`，
`wb=260 wa=111`，`GC_MOE_EPLB_EXTRA_PER_RANK=8`，每臂都开三个 trace 开关。

⚠️ 测量陷阱（已踩过两次，务必照做）：

1. **`MEASURE_STEPS` 必须是 100。** 用 10 时 warmup 的 100 步还在 GPU 队列里，
   10 步窗口被稀释（BS=64 报 18.10 而真实 27.49；判据是 `submit/warm ≪ 1`）。
2. **每臂之间必须彻底清 GPU。** vLLM worker 的线程名叫 `VLLM::Worker_TP`，
   `pkill -f real_decode` 抓不到，残留会占 55 GB/卡并使下一臂报
   `Free memory ... less than desired` 或 `Gloo connectFullMesh refused`。
   用 `scripts/_clean_gpu.sh`（按驱动报告的 PID 杀 + 等端口释放）。
3. `fine_rows` 的 epoch 与 `tl_rows` 的 `step_tag` **不重叠**（前者是
   `FINE_MIN_EPOCH` 之后最先填满的 65536 条，后者是最近 256 步的环形缓冲），
   取时间基准只能用 `fine_rows` 自己的首个 `slot_begin`。

## `smreuse/` — SM-reuse 臂（20 臂表的最后一列）

`SMRY_{32,64,128}.json` 与 `SMRX_256.json`：`GC_MOE_SM90_SM_REUSE=1`，
即 ECO + 一个跑在 dispatch 腾出 SM 上的额外 compute role（role 6）。

其余配置与 `x16/` 完全相同（100 步 warmup + **100 步测量**，tracing 全开）。
`SMRX_256.json` 额外带完整 `eco_trace`（8 rank 的 `fine_rows`），
`docs/plots/smreuse/smreuse_bs256.png` 由它生成。

role 6 的 M 块在 `fine_rows` 里用 **id >= 1000** 标记（role 2 是 0..70），
所以在 trace 里可以直接区分两者的工作量。
