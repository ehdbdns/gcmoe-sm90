## 结论

1. **extra=8 在四档全部优于 extra=4**（ECO 臂：−1.6% ~ −3.3%）。
2. **extra=4 下 ECO 在大 batch 失去优势**：BS=256 时 ECO 比 RR 慢 3.57%，
   而 extra=8 时 ECO 快 2.09%。
3. 原因：extra=4 只有 `max_copies=3`，副本储备少 ⇒ quota 切分的腾挪空间小，
   大 batch 下难以把热点专家的负载摊到足够多的副本上。
4. ★ 注意：**ms 差异不能只归因于 M 块数**。BS=128/256 时两个冗余度的块数完全相同
   （33 / 42），extra=8 仍然快 1.7% / 3.3%；而 BS=32 时 extra=8 的块数更多（19 vs 10）
   却仍然更快。说明差异来自槽上的 token 分布（进而影响 GEMM 的实际 tile 形状），
   而不只是块的数量。
5. 因此**最终配置取 extra=8（P=448）**。
