### `controlled_inputs_match` 在 BS512/1024 为 False 的原因（已定位）

脚本 `compare_ep8_linear.py::workload()` 采集 115 个字段。逐字段比对：

| 字段 | 是否一致 |
|---|---|
| `prompt_hash` | ✅ 完全相同（BS512 `e7c4aee9…`、BS1024 `d7eeeb50…`）|
| `output_hash` | ✅ 完全相同（BS512 `a6e9d5ea…`、BS1024 `50ec1018…`）|
| `prefill_steps` | ✅ 267 / 645，两轮相同 |
| 逐 rank 路由 `ids` / `weights` / `demand` | ✅ 相同 |
| `batch_order` / `warm_native` / `placement` / `logical_weights` | ✅ 相同 |
| **KV 快照读回哈希（`prefill_snapshot.readback_sha256`、`snapshot.readback_sha256`）** | **❌ 16 个位置不同（stats 8 + measured 8）** |

也就是说：**输入、反馈、路由、放置、逻辑权重全部逐位一致，只有 KV 二进制读回哈希不同。**

原因：本轮每档按任务书要求"重新生成自己的统一参考 token、统计与测量 route bank 及两次边界 KV"，旧轮是另一次独立运行生成的 KV。KV 缓冲区的读回哈希覆盖了内存布局/分块等运行期细节，跨运行不保证逐位相同。

**结论**：BS256 三档的跨轮对照在全部字段上受控（`✅`），可作严格比较；**BS512/1024 的对照只差 KV 哈希一项**，其余受控，其 `change_pct` 与 `vs_rr_delta_pp` 应视为"输入等价"而非"逐位受控"的对照。

注：BS512/1024 的 `change_pct`（+1.16% … +3.49%）与 BS256 的（+0.46% … +3.57%）量级相同，说明性能变化并非由这一项引起。

**新旧轮同时改变了启动顺序（shared L1 优先）与 ECO 价格（线性 + 2A），此比较衡量的是组合效果**，不能拆分归因。

### BS256 ECO 与 `previous_wa1_us` 的对照

`historical.csv` 中 BS256/eco 行的 `previous_wa1_us = 824.15`、`change_pct_vs_wa1 = +5.86%`。这两列来自回放轮 `d29002c` 的 wa=1（合成路由、slack 91），与本轮整模实测（真实路由、线性价格 + 2A、slack 92）口径不同，**不构成同条件胜负**，仅作量级参考。
